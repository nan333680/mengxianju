# 设置生效逻辑审计（v0.4.3）

> 起因：用户要求"全方面检查设置生效逻辑，记住，是所有"。
> 目的：确认【界面上能改的每一项】都真的会改变东西 —— 而不是改了没用、或者界面承诺的
> 和代码里做的不是一回事。下面写的每条结论都有出处（文件:行）或可执行证据（e2e）。

## 一、查法

1. **静态读点**：把全部设置键列出来（全局 DEFAULTS 40 个 ∪ 角色级 CHAR_KEYS 25 个 ∪
   群设置 11 个 = 61 个），逐键找"谁读它"，凡读点只出现在回显/写回函数的列为嫌疑。
2. **界面绑定**：`www/index.html` 里 147 个 `s- / g- / e-` 前缀控件逐个找绑定，
   对"扫不到绑定"的人工复核（这类多半是显示元素，如 `-brief` / `-count` / `-tip`）。
3. **测试覆盖**：把 137 个 e2e 逐键 grep 一遍，找出【从来没有被任何测试碰过】的键。
4. **动态验证**：对盲区键补新套件，走"界面点一下 → 落库的值 → 产物上看得见的差别"三段。

## 二、三层设置是怎么合并的（结论：逻辑成立）

- 角色级参数走 `CHAR_KEYS`（`www/js/app.js:240` 之前）25 个键；`effSettings(char, s)`
  （`www/js/app.js:263-271`）在 `globalOverride` 为假时，角色设过的键盖掉全局、没设过的回退全局。
- `FOLLOW_KEYS = ['descLevel', 'detailDrive']`（`www/js/app.js:240`）额外管"跟随全局"的三态：
  设为 `'global'` 时把角色身上这个键删掉（`www/js/app.js:7787` 附近的 `saveCharEdit`），
  于是自然回落到全局值 —— 而不是靠一个独立开关。
- `povLock` / `povStyle` / `thinkMode` / `appearance*` 全部经 `effSettings` 进 `P` 后由
  `buildStablePrompt` / `buildTurnNote`（`www/js/persona.js`）读，与 `app.js` 写请求体时读的
  是同一个 `P`，不存在"两处各读一份"的漂移。
- **改完立刻生效**：`saveCharEdit()`（`www/js/app.js:7701-7806`）末尾
  `await loadChars(); await selectChar(curCharId); resetTo('chat');`，而 `selectChar` 里
  `curChar = await chars.get(id)`（`www/js/app.js:1402`）—— 不需要退出重进聊天。
- 群设置是另一条线：`saveGroupSettings(silent)`（`www/js/app.js:8682+`）把
  name / groupNote / heNote / placeNote / myEnv / speakMode / allowSilence / autoScene /
  narrative / showNarration / sceneLen / sceneMix / verbosity / kaomojiStyle / descLevel /
  detailDrive / povStyle / kaomojiFreq / emojiFreq / temperature / maxTokens 写进群角色记录本身，
  由群聊分支直接读。`sceneMix` 是三态：选 `auto` 时 `delete g.sceneMix`（用默认抽签）。

## 三、查出并修掉的问题（1 个）

### 1. `memDedupeEvery`：一个改了不生效的死旋钮 —— 已删掉

- 界面原来有 `#s-mem-dedupe`「每隔多少轮查重合并一次」（`www/index.html:699-701`），
  但全仓库只有两处读它：`www/js/app.js:10554`（回显）与 `10557`（写回）。
- 真正的门槛在 `www/js/app.js:6538-6555`：
  `const grew = ... listAll.length - lastLen;`
  `const grownEnough = grew === null || grew >= Math.max(3, Math.floor((S.memLimit || 20) / 2));`
  `const nearlyFull = listAll.length >= Math.max(3, Math.floor((S.memLimit || 20) * 0.8));`
  早退那一行的条件里没有它。`www/js/app.js:6494-6503` 的注释写明 v1.21.28 起**故意**改成按
  "新增记忆条数"算 —— 该不该查重取决于记忆攒了多少，跟聊了几轮没关系。
- 处理：**删旋钮、不改行为**。若把它接到门槛上，等于改掉所有人现有的整理频率，风险大于收益。
  改到的文件：`www/index.html`（三层说明 + 换成一段解释）、`www/js/app.js`（DEFAULTS 去掉该键）、
  `www/js/presets.js`（PARAM_DEFAULTS 去掉并改成实话注释）、`docs/开发记录.md`（第 2 条改写），
  以及 8 个 e2e（4 个改断言、4 个清 seed 残留）。

## 四、看着可疑、但确认没问题（记下来免得下次再查一遍）

- `www/js/presets.js` 的 `PARAM_DEFAULTS` 里还留着 `memSummarizeEvery` / `memLimit`：
  它只喂 `openCharEdit` 的表单预填（`www/js/app.js:7513`），而表单里没有这两个控件，
  所以它永远读不出来 —— 但真值以 `app.js` 的 DEFAULTS 为准，不影响行为。已加注释。
- `globalOverride`：已废弃的"全局统一"开关，界面早就没了，但 `effSettings` 运行时**仍然读它**
  （`www/js/app.js:268`）。启动时强制 `S.globalOverride = false` 并写回库
  （`www/js/app.js:1186-1191`），同时列进 `NO_IMPORT_SETTINGS`（`www/js/app.js:11548-11552`）
  不采纳导入值 —— 否则一份老备份就能让所有角色的独立参数静默失效。留着它是对的，不是死代码。
- 12 个"扫不到绑定"的控件全是显示元素或绑定写法不同，例如
  `$('e-look-apply').onclick = async () => {`（`www/js/app.js:12622`）、
  `const renderMode = (cur) => renderSeg('e-mode', MODE_PRESETS, cur, k => applyMode(k));`
  （`www/js/app.js:7674`）。没有"点了没反应"的控件。

### 另修：e2e/e2e-new.mjs 第 3 节（token 用量）长期红着

原样跑是 17 通过 / 3 失败，三条全在同一处：「AI 气泡上显示了 token 用量」「格式是 ↑输入 ↓输出」
「usage 存进了消息」。原因不是产品坏了，是**这一套没有 mock 模型接口**：
设了 `sk-test` 就直接打真网，拿不到任何响应，自然也没有 usage 帧
（产品侧 usage 只来自 SSE：`www/js/api.js:400` `if (j.usage && onUsage) onUsage(j.usage);`，
再经 `www/js/app.js:5836` `if (i === 0 && usage) am.usage = usage;` 记到这一轮的第一条消息上）。

照 `e2e/e2e-archive.mjs` 的做法修掉了：本机 http server 上加一个
`/api/chat/completions` 分支回 SSE（含一帧 `usage:{prompt_tokens:12,completion_tokens:7,total_tokens:19}`），
并把 `#s-baseurl` 指到 `http://127.0.0.1:<port>/api`。修完 **20 / 0**。

### 顺手记下的一条运维知识（以后写设置相关的 e2e 用得上）

设置页里的控件是**进入设置页那一刻**才绑定和渲染的（`www/js/app.js:3423` → `bindSettings()`）：
不先走一遍 `#btn-settings` → 抽屉里的 `[data-wb-drawer="settings"]`，那么 `#s-input-h` /
`#s-search-vendor` 这些节点虽然在 DOM 里，但里面是空的、onclick 也没挂 —— 点了没反应。
第一次写 `e2e/e2e-settings-blind.mjs` 时踩了：14 条失败全是"点了没反应"，不是产品坏了。
