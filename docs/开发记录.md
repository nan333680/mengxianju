# 开发记录

给要改这份代码的人：它由哪些部分组成、数据放在哪、几个核心机制怎么运转、怎么构建和测试。

> 本文件不包含本机路径、密钥和开发过程记录。

## 一、这是什么

安卓端 AI 伴侣 App。**纯前端**：

- 没有后端、没有服务器、没有账号系统
- API Key 由用户自己填，请求从 App 里直连模型服务商
- 全部数据在手机的 IndexedDB 里，不上传

| 层 | 用什么 |
|---|---|
| 界面 | 原生 HTML / CSS / JavaScript（ES Module）。**无框架、无构建步骤** |
| 外壳 | Capacitor 8（WebView 套壳） |
| 打包 | Gradle，脚本在 `tools/build-apk.ps1` |
| 测试 | puppeteer-core 驱动 Chrome，端到端脚本 `e2e-*.mjs` |

`www/` 改完刷新即生效，没有编译环节 —— 这是刻意的：包体小、调试快。

## 三、数据

IndexedDB，库名 `ai-companion`，版本 4。

| 表 | 主键 | 索引 | 存什么 |
|---|---|---|---|
| `characters` | `id` | `createdAt` | 角色：名字、人设、开场白、头像（dataURL）、每个角色自己的参数 |
| `messages` | `id` | `charId_ts`、`charId` | 聊天记录。`archived: true` 的是已归档的 |
| `kv` | `k` | — | 键值杂项：全局设置、每个角色的剧情时间、各种"做过了"标记 |
| `memories` | `id` | `charId` | 长期记忆条目 |
| `wbGroups` | `id` | — | 世界书的"角色组"：组名 + 成员 + 该组条目 |
| `wbSolo` | `id` | `charId` | 世界书里给单个角色的条目 |
| `scenes` | `id` | `charId`、`createdAt` | 小说层的一场戏：场景卡 + 拍 + 正文段落。**正文不进 `messages`** |

加新表时必须把 `DB_VER` 加一，并且 upgrade 写成**增量式**（只建不存在的表）——
直接删表重建会把用户数据清空。

## 四、几个核心机制

### 1. 提示词怎么拼

分两层，**这个划分是有意的**：

- `buildStablePrompt(char, settings)` —— 每个字都要稳定。人设、世界书、参数约束都在这。
  同一个角色连续对话时，这段字节不变，服务端的 prefix cache 才能命中，省时省钱。
- `buildTurnNote(charId, settings, topic)` —— 每轮都会变的部分：当前时间、最近记忆、待办。

⚠️ 改 `buildStablePrompt` 时不要往里塞任何随时间变化的东西（日期、随机数、数组顺序不稳定）。
判断标准：同样的输入跑两次，输出必须完全相同。

稳定段内部再分三节，顺序固定：`# 基础设定` → `# 相关设定` → `# 临场设定`。

### 2. 长期记忆

三层，参数在设置里可调：

1. **攒够 N 条消息**总结一次（`memSummarizeEvery`）
2. **新增条数攒够**就把意思相近的条目合并压缩 —— 门槛由上限决定：新增到 `memLimit` 的一半（至少 3 条），或总数 ≥ 80% 上限。（旧版本这里写的是 `memDedupeEvery`「每隔多少轮」，2026-10-15 删掉：查重从 v1.21.28 起就不看轮次了，那个值改了不生效。）
3. **有时限的事**过期自动删

每一轮发给模型的不是全部记忆，而是 `rankMemories(memories, topic, 24)` 挑出来的 24 条：
关键词重合度 × 新近度打分。**用户手动置顶（pinned）的保底进**，不参与打分。

提炼失败时**不能**把消息标记成"已提炼"—— 那会让内容永久丢失。标记只在解析成功后推进。

### 3. 世界书

两层结构，按关键词触发注入：

- **角色组**：一组角色共用一套设定（比如同一部作品里的几个人）
- **单独角色**：只给某一个角色的设定，优先级更高

条目还有"什么时候生效"三档（常驻 / 命中关键词 / 手动开）。

### 4. 剧情时间

不是真实日期，是故事里的时间：第几天、哪个时段、季节、天气。

- 状态在 `kv` 里按角色存（`clock:<id>`）
- 开「时间跟现实走」时另开一个存档位（`clock:<id>:real`），关掉再打开会接着走
- 「时段划分」把"早上/傍晚"映射到具体小时，可在设置里改

### 5. 上下文预算

模型窗口是有限的，但"条数少"不等于"token 少"—— 长人设 + 长世界书 + 20 条长回复一样会撞爆。

做法：先估一遍 token（`estimateTokens`），固定段（人设 / 常驻世界书）**一格不裁**，
剩下的额度给历史，超了就从**最旧的一端整段丢**。撞上 `context_length_exceeded` 时
自动砍一档重发一次，只降一次。

估算刻意往多了算。图片按张算固定值，**不按 base64 长度算**（一张图几十万字符，
按长度估会把历史全砍光）。

### 6. 删除语义

**删除一个角色 = 属于她的一切都删掉**（同一个 IndexedDB 事务，按 `charId` 索引走）：

| 数据 | 处理 |
|---|---|
| `characters` 那条记录 | 删 |
| `messages`（含已归档的） | 删 |
| `memories` | 删 |
| `wbSolo` 里她的单独条目 | 删 |
| `wbGroups` 里她的成员身份 | 从成员列表移除（**组本身保留**，别的成员不动） |
| `kv` 里 `*:<id>` 和 `*:<id>:real` 结尾的键 | 删（扫库匹配，不靠人工维护前缀表） |

删除是**不可恢复**的，所以确认框要说明白删的是什么。

⚠️ 记忆曾经是**故意保留**的（注释写着"记忆是全局共用的，删角色不连坐"）—— 那句是错的：
`memories` 表有 `charId` 索引，每条记忆都属于某一个角色。保留的结果是删完之后
她的记忆变成孤儿，堆在记忆页的「已删除的角色」分组里。

**全新安装进来是空的**：不预置任何角色，聊天页给一句引导。老用户不受影响
（判据是 `kv` 里有没有 `settings` 这条记录）。

## 五、构建

```powershell
pwsh -File tools/build-apk.ps1
```

⚠️ **`.ps1` 必须存成「UTF-8 带 BOM」**。脚本里有中文，而 `powershell`（Windows 自带的 5.1）
读无 BOM 文件时按 GBK 解码 —— 中文变乱码、引号配对崩，报一串 `Unexpected token`。
`pwsh`（7.x）默认按 UTF-8 读，所以用 7 跑时看不出问题，一换 5.1 就炸。
改完脚本自查：`Get-Content tools\build-apk.ps1 -Encoding Byte -TotalCount 3` 要是 `239 187 191`。

两条命令等价，都有 BOM 就能跑：`pwsh -File ...`、`powershell -ExecutionPolicy Bypass -File ...`。

脚本按顺序做：同步 `www/` 到 Android 工程 → Gradle 编译 release → apksigner 验签 →
复制到交付目录。任何一步失败都会中止，不会留下一个看起来像成功的旧包。

签名密钥（`*.keystore`、`keystore.properties`）**不进版本库**，
见 `.gitignore`。丢了密钥就再也签不出能覆盖安装的同一个包。

## 六、测试

```powershell
# 全部（串行，约半小时）
pwsh -File tools/run-regression.ps1

# 单套
node e2e-memory.mjs
```

每套自己起一个静态服务器和一个 Chrome 实例，**必须串行** —— 并发会互相抢，
报出来的是随机假失败。跑之前先杀掉残留的 Chrome。

有几套依赖真实模型 API（要 `DSH_API_KEY` 环境变量），不给 key 时它们会红，
那是缺 key 不是代码坏了。

⚠️ 部分断言直接读源码文本（`includes(...)`）。改注释或挪动代码时留意一下，
别让它们变成假绿或假红。

## 七、版本与发布

- 版本号有两种写法，用途不同：
  - **三段**（`0.3.0`）：对外发布版，推 GitHub、本地长期保留一份
  - **四段**（`0.3.0.1`）：本地迭代版，修一个 bug 就往上加一位，**不上传**；攒够了再打三段版发出去

- `versionName`（字符串）和 `versionCode`（整数）要分开看：前者对外，可以按里程碑重排
  —— v0.3.0 首次公开发布时就从内部的 v1.21.61 改了过来；后者**只能往上加**，
  Android 拿它判升级，调低会让已装的用户装不上（`INSTALL_FAILED_VERSION_DOWNGRADE`）。
- 改版本号要同步三处：`android/app/build.gradle` 的 `versionCode`/`versionName`、
  `www/js/app.js` 的 `WEB_VERSION_FALLBACK`、`CHANGELOG.md`。
  构建脚本会校验前两者一致，不一致直接失败。
- 每个版本另存一份本地完整快照（APK + 源码），供回溯用；
  **不进版本库**，整目录被忽略。
- 包名固定，改了就是另一个 App，老用户的数据不会跟过去。
